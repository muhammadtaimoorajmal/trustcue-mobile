# TrustCue Project State

## Purpose & Workflow
TrustCue is a mobile application designed to explain potential scam indicators in suspicious digital communication. It supports privacy-conscious analysis, providing evidence-based explanations and safe verification steps.
**Core Workflow:** Screenshot/text input -> local extraction -> privacy review -> deterministic checks -> protected AI analysis -> evidence-linked explanations -> local history.

## Technology & Constraints
- **Stack:** Flutter and Dart, with implemented GetX state management, bindings, and navigation. GetX is pinned exactly to `4.7.3` in both manifest and lockfile.
- **Budget:** Zero-budget development. Note: Eventual Play Console registration has a separate cost outside of development.
- **Privacy & AI:** Requires privacy-conscious handling, protected AI credentials, cautious findings, and honest limitations. The app must communicate uncertainty and not invent scam-probability percentages.

## Repository Layout & Branch Workflow
- `frontend/`: The complete Flutter application, including client-side services.
- `backend/`: Future server APIs and protected AI integration.
- `database/`: Database definitions, migrations, fixtures, and DB documentation.
- `docs/`: Shared project documentation.
- `.vscode/`: Narrowly selected portable workspace configuration.
- **Branch Workflow:** Development happens in isolated branches (`frontend`, `backend`, `database`) that map to module responsibilities. Commits are eventually integrated into `main` after verification.

- **Module 42 Verification & Architecture: User-Controlled Privacy-Reviewed Export and Sharing:**
  - **Local Offline Generation Architecture (`ExportFormat`, `ExportOptions`, `ExportReportData`):**
    - Multi-format generation supporting UTF-8 Plain Text (`.txt`, MIME `text/plain`) and paginated PDF (`.pdf`, MIME `application/pdf`) via pure-Dart engines without network access, cloud AI, external converters, or authenticated session requirements.
    - Decoupled from internal storage rows: uses a dedicated data transfer model `ExportReportData` and `ExportFindingItem`, mapping only verified customer-facing fields.
    - Supported inputs: Works seamlessly across currently validated in-memory analysis results (`LocalAssessment`), persisted local historical reports (`SavedReport`), and high-level cloud metadata summaries (`SavedReportSummary`). Cloud summaries without original text snapshots are clearly labeled as metadata summaries without fabricated findings or fake evidence excerpts.
  - **Privacy-by-Default Configuration (`ExportOptions`):**
    - Summaries only by default: reviewed message text, raw text, evidence quotes/excerpts, and AI reasoning explanations are strictly opt-in and toggled OFF (`false`) by default.
    - Zero sensitive leakage: raw OCR image drafts, unreviewed text, original screenshots, account email addresses, authentication tokens, SQLite database paths, and on-device feedback entries are strictly and unconditionally excluded from all export payloads.
    - Honest timestamps and metadata: clearly records both original analysis timestamp and export generation timestamp; displays honest limitations, uncertainty notes, safe verification actions, and explicit disclosures that reports do not guarantee safety or prove fraudulent intent. Never fabricates scam probability scores or safety certifications.
  - **Format Engines & Unicode/Typography Safeguards:**
    - Plain Text Formatter (`PlainTextExportFormatter`): Generates human-readable, beautifully structured UTF-8 text with clean ASCII section dividers, complete Urdu/multilingual character fidelity, and clear boundaries.
    - PDF Export Builder (`PdfExportBuilder`): MultiPage document builder utilizing `pdf: 3.13.1` with a clean dark-on-light theme, metadata summary tables, outcome status badges, structured findings, and numbered recommendations.
    - Latin Font Safeguard & Multilingual Disclosure: Standard Type-1 PDF fonts (`Font.helvetica()`) do not contain character glyphs above code point U+00FF (such as Urdu Nastaliq or emojis) or literal bullet `•` (U+2022). High code points are safely sanitized into descriptive placeholders `[Non-Latin / Urdu script]` to prevent engine crashes, accompanied by a prominent notice advising users to select Plain Text (.txt) export for full multilingual/Urdu fidelity.
  - **Bounded Temporary Storage & Android ShareSheet Lifecycle:**
    - App-private cache directory: Exported files are written exclusively to `<appCacheDir>/exports/` with sanitized, timestamped, collision-resistant filenames (`trustcue_report_<timestamp>.<ext>`).
    - Automated pruning: Every generation cycle automatically prunes stale export files older than 2 hours (`DefaultExportStorageService`), preventing temporary storage accumulation in compliance with TrustCue's data lifecycle policy.
    - System ShareSheet integration: Uses `share_plus: 13.3.1` via `SharePlus.instance.share(ShareParams(...))` with explicit anchor bounds (`sharePositionOrigin`), eliminating deprecated v12 APIs and providing seamless sharing to user-selected apps.
  - **User Experience & Presentation Layer (`ExportReportSheet`, `ExportController`):**
    - Accessible reactive bottom sheet modal with format selector chips (`Plain Text` vs `PDF`), font limitation notice, granular privacy toggle switches, real-time live text preview, copy-to-clipboard action, and Android ShareSheet launcher.
    - Wrapped in a root `Material` widget to ensure standard Material ListTile assertion compliance.
    - Integrations: Easily accessible from both `AnalysisResultsScreen` (AppBar icon & bottom action) and `SavedReportDetailScreen` (AppBar icon & bottom action).
