# TrustCue Project State

## Purpose & Workflow
TrustCue is a mobile application designed to explain potential scam indicators in suspicious digital communication. It supports privacy-conscious analysis, providing evidence-based explanations and safe verification steps.
**Core Workflow:** Screenshot/text input -> local extraction -> privacy review -> deterministic checks -> protected AI analysis -> evidence-linked explanations -> local history.

## Technology & Constraints
- **Stack:** Flutter and Dart, with implemented GetX state management, bindings, and navigation. GetX is pinned exactly to `4.7.3` in both manifest and lockfile.
- **Budget:** Zero-budget development. Note: Eventual Play Console registration has a separate cost outside of development.
- **Privacy & AI:** Requires privacy-conscious handling, protected AI credentials, cautious findings, and honest limitations. The app must communicate uncertainty and not invent scam-probability percentages.

## Repository Layout & Branch Workflow
- `frontend/`: The complete Flutter application, including client-side services.
- `backend/`: Future server APIs and protected AI integration.
- `database/`: Database definitions, migrations, fixtures, and DB documentation.
- `docs/`: Shared project documentation.
- `.vscode/`: Narrowly selected portable workspace configuration.
- **Branch Workflow:** Development happens in isolated branches (`frontend`, `backend`, `database`) that map to module responsibilities. Commits are eventually integrated into `main` after verification.

- **Module 34 Verification & AI Output Validation Architecture:**
  - **Strict Output Validator (`OutputValidator`):** Enforces strict top-level JSON dictionary shape, rejecting duplicate JSON keys (`_strict_object_pairs_hook`) and special numeric constants (`NaN`, `Infinity`, `-Infinity`). Restricts keys strictly to canonical schema without unauthorized properties. Bounded limits: max 20 findings, max 5 evidence references per finding, max 10 uncertainty notes, max 10 suggested actions.
  - **Prohibited Semantic Claims:** Actively scans output strings for prohibited numerical risk scores/percentages (e.g. `95% scam probability`), absolute safety certificates (`100% safe`, `guaranteed safe`), definitive fraud claims (`guaranteed scam`), fictitious device compromises (`phone is hacked`), and executable markup (`<script>`, `<iframe`, `javascript:`).
  - **Exact Evidence Grounding (`EvidenceGrounder`):** Preserves submitted reviewed text byte-for-byte without trimming, case-folding, whitespace collapsing, or Unicode normalization. Enforces exact substring equality.
  - **UTF-16 Code-Unit Interoperability:** Builds authoritative UTF-16 offset maps mapping Python character positions to Dart `String` UTF-16 code units. Strictly verifies that offsets do not split surrogate pairs of supplementary astral characters (verified with emoji 🛡️ `\u{1F6E1}` and RTL Urdu scripts).
  - **Repeated Quotation Disambiguation Policy:** When identical quotations appear multiple times, requires valid verified offsets from provider; ambiguous duplicates without offsets are strictly rejected with `AmbiguousQuotationError`. Arbitrary first-match selection is prohibited.
  - **Quota Accounting Policy for Completed Inference:** When the upstream provider completes inference, quota is committed before validation. If output validation or evidence grounding subsequently fails, quota remains committed because upstream provider resources/tokens were expended. This prevents free inference abuse loops via adversarial inputs.
  - **Gating Before Side Effects:** Public route `POST /api/v1/analysis/ai` checks `ENABLE_CLOUD_AI` and Module 35 consent gate before reserving quota or acquiring concurrency locks, returning honest 503 without database churn or side effects.
  - **Cross-Language Contract Tests:** Verified with 119 automated backend tests (34 new tests in Module 34) and 4 Flutter consumer contract tests in `ai_contract_compatibility_test.dart`.
